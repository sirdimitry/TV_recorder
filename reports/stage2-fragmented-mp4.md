# Этап 2: фрагментированный MP4

Выбран фрагментированный MP4 по указанию пользователя.

## Поведение

- Прямые потоки, отдельные видео/аудиовходы и запись экрана пишутся во временный MP4: frag_keyframe + empty_moov + default_base_moof; frag_duration=1000000 мкс.
- Задание восстановления сохраняется в data/pending_recordings до запуска FFmpeg, с fsync. Пути сохраняются абсолютными, включая выбранные пользователем папки.
- После остановки FFmpeg выполняется remux (-c copy) во второй временный MP4 с faststart. Проверяются читаемость, наличие дорожек и отсутствие значительного сокращения длительности. Только затем файл публикуется под итоговым именем.
- Публикация через hard link отказывается перезаписывать существующий файл; исходник удаляется после fsync итоговой папки. На файловой системе без поддержки hard links сборка выдаст ошибку и сохранит исходник, это ограничение текущей реализации.
- При ошибке исходник и задание восстановления сохраняются; текущая задача показывает временный файл и частичный результат либо ошибку обработки.
- При запуске приложение предлагает восстановить оставшиеся записи. Отказ сохраняет их для следующего запуска. Восстановление выполняется в фоне.
- flock исключает активные записи, в том числе из другого экземпляра приложения, и параллельное восстановление одной записи.
- Потоки завершения больше не daemon: обычный выход Python не обрывает сборку. У remux таймаут 120 секунд, при превышении исходник сохраняется. У ускоренного захвата — отдельный таймаут с учётом длительности, как и прежде нужна перекодировка.

## Проверки

- Полный прогон: **122 теста, 19.382 секунды, OK**. Журнал: stage2-tests.txt.
- Принудительный SIGKILL FFmpeg: доступные фрагменты восстановлены в обычный MP4.
- Нормальная сборка: в результате нет moof; хеши закодированных видеопакетов совпадают.
- Проверка сохранности аудио и видео через streamhash.
- Существующий итоговый файл не перезаписывается, исходник сохраняется.
- Ошибка запуска remux сохраняет исходник и метаданные.
- Активный файл исключён из восстановления.
- Ускоренная запись получает нормальную длительность.
- Smoke через настоящий Recorder на синтетическом 720p H.264/AAC: 1 и 4 записи, миниатюры включены/выключены; все 10 файлов completed. Сырые результаты — stage2-smoke.json. Это короткая функциональная проверка, её CPU нельзя напрямую сравнивать с этапом 1 (разная длительность, дополнительные проверки и remux).

## Границы

Последний недописанный фрагмент после аварии может быть утрачен. Безопасность при физическом отключении питания не проверена. Конвертация временно требует дополнительного места размером с запись. Старые обычные MP4 без метаданных автоматически не восстанавливаются. Полный UI-диалог, реальный эфир и avfoundation не проверялись вручную; механизм screen capture проверен на уровне формирования команды и восстановления синтетического ускоренного видео.

Исходная папка и установленное приложение не изменены. DMG не собирался, релиз и push не выполнялись.
