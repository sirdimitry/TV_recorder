# Этап 5 — пауза эфира через части и объединение без перекодирования

## Поведение паузы

Прямые телеканалы (is_live_channel) больше не ставятся на SIGSTOP. Нажатие паузы помечает текущую часть как завершённую пользователем и отправляет мягкое завершение FFmpeg. При отсутствии реакции за STOP_GRACE (5 секунд) процесс принудительно завершается; доступные фрагменты сохраняются механизмом этапа 2.

Супервизор финализирует часть и остаётся в состоянии паузы без работающего процесса записи. При продолжении запускается новая часть. Быстрое возобновление до окончания финализации обрабатывается через pause_pending: второй процесс появляется только после завершения и обработки первого. SIGCONT не отправляется. Пауза не расходует retry_count; нумерация частей отделена от счётчика восстановления.

При продолжении HLS live_start_index установлен в -1 для каждого HLS-входа, включая отдельные видео и аудио: открывается наиболее свежий сегмент вместо прежней стартовой позиции -3. Для произвольного прямого live-потока актуальность зависит от сервера. Задержка самого источника не устраняется.

Остановка, выход, ошибка диска/финализации и абсолютный deadline запрещают продолжение. Во время ожидания паузы deadline проверяется каждые 0.2 секунды. Время паузы учитывается в таймере; период расписания не переносится. Готовые ролики и browser capture используют прежний SIGSTOP/SIGCONT.

UI показывает «Пауза» и постоянную подсказку «На паузе прямой эфир пропускается». Кнопка продолжения доступна и после выхода первого FFmpeg. Завершённая запись с паузами остаётся частичной со статусом «Сохранено с паузами»: пропущенный эфир не скрывается.

## Объединение

Добавлен core/recording_merge.py и кнопка «Объединить» после завершения задачи с несколькими частями.

Перед объединением ffprobe сравнивает порядок/число потоков, кодеки, профиль, уровень, размеры, pix_fmt, параметры аудио, time_base и SHA-256 extradata. Проверяется читаемость и известная длительность каждой части. Несовместимые или нечитаемые части отклоняются без изменения исходников.

FFmpeg concat demuxer с auto_convert=0 и -c copy создаёт отдельный временный MP4 с faststart. Проверяется итоговая длительность, наличие видео/аудио и неизменность параметров потоков. Публикация через hard link не перезаписывает существующий файл; после fsync удаляется только временная копия. Части остаются на диске. Кнопка папки после успеха указывает на объединённый файл; повторное объединение той же задачи заблокировано.

Перед сборкой проверяется место для дополнительной копии плюс резерв активных записей на этом томе и 256 МиБ. Ошибка сборки оставляет исходники. Операция идёт вне UI-потока; рабочий поток учитывается при завершении приложения.

## Проверки

**Полный прогон: 155 тестов, 68.437 секунды, OK.** Журнал: stage5-tests.txt. Проверка git diff --check пройдена.

Новые тесты используют настоящий FFmpeg с синтетическим H.264/AAC и проверяют:

- пауза/возобновление live не отправляют SIGSTOP/SIGCONT;
- продолжение после полного выхода FFmpeg;
- две паузы создают три читаемые части с разными именами, retry_count остаётся нулевым;
- быстрый resume не запускает второй процесс до обработки первого;
- stop, shutdown и deadline во время паузы не создают новых процессов;
- возобновлённый HLS использует live_start_index=-1;
- объединение реальных паузных частей сохраняет видео/аудио, длительность и все оригиналы;
- отдельный тест сравнивает SHA-256 конкатенации исходных видеопакетов с видеопакетами результата: совпадение;
- пути с пробелами и апострофом корректно обрабатываются manifest;
- разные разрешения отклоняются, существующий результат не перезаписывается;
- отказ проверки свободного места оставляет все части и не публикует результат.

## Границы

Нативные кнопки вручную не нажимались, реальный сетевой эфир на паузе не проверялся. В тестах HLS-команды проверяются по аргументам, медиаданные подменяются локальным синтетическим источником. Проверка совместимости консервативная: некоторые потенциально объединяемые части могут быть отклонены. Побайтовая неизменность проверена для видеопакетов; для записи с аудио проверены наличие дорожек, совместимость параметров и общая длительность, но не точность склейки по каждому аудиосэмплу. Пропущенный эфир не восстанавливается; части разделены до нажатия «Объединить». Кнопка использует task.parts текущего сеанса; автоматическое объединение восстановленных после перезапуска файлов пока отсутствует. Для публикации по-прежнему нужна файловая система с hard links.
