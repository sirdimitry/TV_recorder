# TV Recorder 1.1.50 — кандидат с докачкой YouTube

Собрано приложение packaging/dist/TV Recorder.app и архив packaging/TV_Recorder_1.1.50_youtube_resume.zip. Версия бандла проверена: 1.1.50. Подпись ad-hoc; codesign --verify --deep --strict пройден. ZIP проверен на CRC. Установленное приложение не заменялось, публикация не выполнялась.

## Изменения

Новые загрузки полного видео YouTube используют отдельный процесс yt-dlp: продолжение .part/.ytdl, повторное извлечение свежих URL, фиксированные форматы и проверка идентичности видео. Пауза останавливает передачу, сохраняя данные в .tv-download-ID рядом с загрузкой. Автоматические повторы ограничены; после их исчерпания доступны ручное продолжение и сохранение задачи через перезапуск приложения. Повторного запуска той же задачи одновременно не допускается. Во время обработки MP4 пауза отключена. Отмена удаляет временные части после подтверждения.

Итоговый MP4 публикуется после проверки видео, звука и длительности. Превью во вкладке загрузок останавливается и скрывается, боковая панель записей скрыта: список получает доступную рабочую область.

## Проверки

- Полный прогон после изменения движка: 221 тест, 80.075 с, OK.
- Финальный специализированный прогон: 9 тестов, 11.387 с, OK. Включает реальный HTTP Range на локальном сервере: пауза, восстановление задачи после перезапуска, докачка и побайтовое сравнение с оригиналом; обрыв сети с исчерпанием повторов и ручным продолжением; раздельные видео и аудио с паузой во время аудио, продолжением и проверкой длительностей обеих дорожек после remux.
- Проверка замены форматов/ID/длины источника: несовместимые части не смешиваются.
- Встроенный worker из собранной .app запускается с изолированным TV_RECORDER_HOME и возвращает ожидаемый JSON об ошибке для заведомо неверного URL (ожидаемый код 1); GUI при этом не запускается. Первый запуск без изолированного профиля был отклонён из-за запрета записи логов в пользовательскую папку; повтор с QA-профилем успешен.
- compileall и git diff --check пройдены.

## Границы проверки и использования

Реальное подключение к YouTube в этой сборке не проверялось. Тест с локальным сервером доказывает механизм продолжения, но не доступность сайта из конкретной сети. Полный интерактивный обход окна на macOS не выполнялся.

Старые неполные MP4, другие сайты, эфир и загрузка обрезанного фрагмента не переводятся на этот механизм. Если сервер не поддерживает Range, yt-dlp может перекачать отдельную дорожку. При изменении форматов или повреждении полного контейнера задача остаётся на паузе с сохранением данных; продолжение не гарантировано. Публикация использует hard link в той же папке: на файловой системе без hard links итоговая публикация может быть недоступна, временные данные сохраняются.
