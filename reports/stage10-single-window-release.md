# Этап 10 — одно окно и подготовка тестовой сборки

## Результат

Код и тестовая .app подготовлены. Этап выпуска **не закрыт полностью**: визуальная приёмка на macOS и создание DMG заблокированы текущей средой. ZIP с .app служит альтернативным тестовым пакетом. Публикации, push и замены установленной версии не было.

## Интерфейс

- Монитор — страница основного окна. При возврате освобождаются подписка на миниатюры, прослушивание и UI callbacks; процессы записи продолжают работу.
- Настройки путей, сведения о программе, добавление/редактирование каналов и ссылок, добавление загрузки — страницы с «← Назад». Формы прокручиваются; главное рабочее пространство сохраняет свои виджеты и состояние под страницей. Несохранённый ввод при выходе отменяется.
- Предупреждения и подтверждения — внутри того же окна, без Toplevel. Ожидание ответа обслуживает события Tk. Закрытие приложения отменяет ожидающий вопрос; переход на новую страницу также отменяет его.
- При закрытии формы отменяются её отложенные callbacks. Поздний результат фонового распознавания ссылки отбрасывается вместо обращения к уничтоженным полям.
- Миниатюра ссылки вызывает существующий встроенный предпросмотр вместо запуска отдельного ffplay. Если прямая ссылка ещё недоступна, отображается объяснение. Неиспользуемые popup-функции истории удалены.
- Системные выборы файла/папки остаются стандартными. Исключение: браузерный захват требует отдельного окна браузера с исходным видео. Он не перенесён внутрь Tk: это отдельный процесс для воспроизведения и захвата экрана.

## Структура и зависимости

- RecordingTask вынесен в core/recording_task.py; импорт из core.recorder сохранён для совместимости.
- Общие страницы и сообщения вынесены в gui/inline_pages.py и gui/inline_messages.py.
- requirements.txt подключает runtime-зависимости; PyInstaller — в requirements/build.txt. Зафиксированы проверенные прямые версии, включая hooks PyInstaller, в requirements/tested-constraints.txt. Это не полный транзитивный lock-файл и не заявление о самых новых версиях.
- APScheduler ограничен веткой 3.x, с API которой работает планировщик.
- Добавлен workflow macOS/Python 3.12: установка FFmpeg, компиляция, unittest и проверка shell-скриптов. Workflow подготовлен локально; на GitHub ещё не запускался.
- TV_RECORDER_HOME позволяет тестировать отдельный профиль данных/логов/медиа, не перемещая ресурсы исходников/бандла.

## Сборка

Исправлен collect_all('webview') вместо имени дистрибутива pywebview. Генератор ICNS использует Pillow вместо iconutil. Кэш PyInstaller находится в packaging/build/cache. Оба shell-скрипта принимают PYTHON_BIN. Для DMG добавлены простой режим без оформления Finder и SHA-256 при успешной сборке.

Собрана **packaging/dist/TV Recorder.app**, версия 1.1.49, Python 3.12.4, PyInstaller 6.6.0. Подпись ad-hoc, `codesign --verify --deep --strict` пройдена. Это не нотарифицированный публичный релиз.

Бинарники FFmpeg/ffplay/ffprobe обеих архитектур скопированы из существующего локального кэша прежнего проекта; arm64 FFmpeg сообщает 7.1. Архитектуры проверены build.sh, но сама Python-сборка рассчитана на Apple Silicon. Упаковка Intel FFmpeg не делает .app универсальной.

Тестовый архив: packaging/TV_Recorder_1.1.49_stage10_test.zip, 227314849 байт, CRC всех записей ZIP проверен. Рядом SHA-256. В архив включена обычная сборка; при ручном запуске она использует стандартный профиль приложения. Для изоляции можно запускать исполняемый файл с явно заданным TV_RECORDER_HOME, как описано в README. Изолированная QA-копия с отдельным bundle ID и LSEnvironment осталась в work-ui; её запуск не подтверждён.

## Осталось перед выпуском

1. Запустить .app на обычном macOS-сеансе и проверить формы/монитор/подтверждения при минимальном размере окна, прокрутку и кнопку возврата. Проверить, что одновременно виден один корневой интерфейс.
2. Во время реальной записи перейти в настройки/монитор и обратно; подтвердить сохранение выбранного источника, расписания и продолжение записи.
3. Пройти реальные сетевые сценарии и браузерный захват; автоматические тесты не доказывают работу всех внешних сайтов.
4. Собрать и смонтировать DMG там, где доступны службы образов диска, и проверить установку копии. ZIP не заменяет эту проверку.
5. После визуальной приёмки решить вопрос версии и публикации. Текущий кандидат не объявлять проверенным публичным релизом.
