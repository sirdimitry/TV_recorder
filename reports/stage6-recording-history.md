# Этап 6 — проверка полноты, история и единый итоговый файл

## Реализовано

- Общая оценка MediaAssessment: читаемость, видео, ожидаемый звук, длительность видео и аудио, ожидаемая длительность, численный недобор и список причин. Нормальный код выхода FFmpeg больше не скрывает короткий результат.
- Для оценки сохранённого видео используется длительность видеодорожки, если известна, затем длительность контейнера. Более длинное аудио не маскирует потерю видео. NaN/inf/некорректные и отрицательные длительности не считаются валидными.
- Допуск длительности: max(1 с, min(5 с, 2% ожидаемой длительности)). Для live ожидаемая длительность сеанса — интервал работы до остановки/deadline, включая паузы и переподключения. Фактическая длительность — сумма читаемых частей; ошибки обработки без пригодного видео в сумму не входят. Для VOD используется заданный фрагмент/известная длительность источника; намеренная ранняя остановка не сравнивается с полной длиной ролика.
- Для прямых телеканалов по умолчанию ожидается звук; API и данные канала позволяют явно задать expect_audio=False для намеренно немого источника. Для screen capture ожидание звука соответствует доступности loopback.
- История RecordingHistory: отдельный JSON на сеанс, атомарное сохранение, .bak, блокировка владельца. Сохраняются части, пути, ожидаемая и фактическая длительность, дорожки, состояния и события. Нет записи исходных заголовков/URL; URL в ошибках маскируются. Файлы истории исключены из Git.
- Блокировка отличает аварийно завершённый сеанс от записи другого работающего экземпляра. После восстановления файла обновляется прежний сеанс; если истории ещё не было, создаётся запись восстановления с неподтверждённой полнотой.
- Ошибка истории не останавливает FFmpeg. Ошибка уведомления об истории тоже не превращает успешно восстановленный файл в ошибку восстановления.
- В панели добавлена «История» (100 последних сеансов), нажатие на статус открывает причины, части и события. Очистка завершённых строк не удаляет историю.

## Дополнение по пожеланию пользователя: один MP4 автоматически

После завершения записи с несколькими пригодными частями запускается сборка без перекодирования. Один итоговый файл *_joined.mp4 становится адресом результата в callback, истории и кнопке папки. Ручное действие больше не требуется. Промежуточные неудачные попытки без пригодных данных пропускаются при сборке, но остаются в истории. Оригиналы сохраняются.

Проверка совместимости и безопасная публикация реализованы на этапе 5. Если параметры изменились или места недостаточно, автоматическая сборка не уничтожает части: причина сохраняется, доступна ручная повторная попытка. Частичный статус не меняется на полный после склейки. Пропущенный эфир из ТВ-архива автоматически не подкачивается. Восстановленные после полного перезапуска отдельные части автоматически в одну сессию пока не склеиваются.

## Проверки

**Полный прогон: 174 теста, 73.603 секунды, OK.** Журнал: stage6-tests.txt. Проверка git diff --check пройдена.

Новые тесты проверяют численный недобор, допустимое отклонение, неизвестную и некорректную длительность, пропавший/укороченный звук, видео короче аудио, сохранность истории после перезапуска/очистки UI, резервное восстановление, параллельные события, блокировки владельца между экземплярами истории, отсутствие исходных секретов, независимость записи от ошибок истории и уведомлений, текст подробностей и автоматическую сборку.

Интеграция с настоящим FFmpeg: двухсекундный исходник при ожидании пяти секунд получает partial и недобор около трёх секунд; дорожки и результат сохраняются в истории. Восстановление MP4 после моделирования аварии обновляет прерванный сеанс. Сценарий с двумя паузами проверяет автоматическую сборку одного файла без ручного вызова. Все предыдущие регрессионные сценарии включены в полный прогон.

Попытка нативного UI-smoke завершилась кодом 134 при запуске Tk без диагностического текста. Причина не установлена; успешная проверка реальных окон не заявляется. Формат подробностей и логика состояний проверены тестами. Реальные сетевые обрывы новой версией пока не проверены.
