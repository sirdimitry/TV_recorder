# Этап 7 — защита Mac от автоматического сна

## Реализация

Добавлен core/sleep_inhibitor.py с временными macOS power assertions через системный /usr/bin/caffeinate. Параметры проверены по локальной документации Apple caffeinate(8).

- Прямая запись использует `-i -w <PID приложения>`: запрет автоматического сна системы без запрета гашения дисплея.
- Захват браузерного плеера дополнительно использует отдельную группу `-i -d -w <PID приложения>`, чтобы захват экрана не продолжался с погашенным дисплеем. Эта группа удерживается только screen capture; её освобождение не снимает защиту прямых потоков.
- В каждой группе уникальные ключи сеансов объединяются в набор. Первое получение запускает один helper, последняя отдача завершает его. Повтор одного ключа и освобождение неизвестного ключа безопасны.
- Ключ обычной записи берётся перед запуском FFmpeg и снимается в finally рабочего потока. Неудачный запуск тоже освобождает ключ.
- Между частями, во время восстановления, пауз и финальной автоматической сборки ключ сохраняется. Ручное объединение после завершения записи берёт отдельный ключ и освобождает его в finally.
- Выход из приложения закрывает обе группы и запрещает новые ключи. -w привязывает их к процессу приложения: после kill/аварии assertions автоматически исчезают.
- Если helper неожиданно завершился, таймер Recorder повторно запускает его при существующих ключах. Повторный запуск ограничен интервалом 10 секунд. Ошибка вызывает предупреждение и не отменяет запись.
- Освобождение ждёт завершения helper, при зависании применяет kill с ограниченным ожиданием. Ошибка самого уведомления не прерывает работу.
- Постоянные настройки питания не изменяются. На других платформах helper не запускается.

## Проверки

**Полный прогон: 188 тестов, 73.606 секунды, OK.** Журнал: stage7-tests.txt. Проверка git diff --check пройдена.

Unit-тесты: совместное владение несколькими задачами; параллельное получение ключей; повторное получение одного ключа; освобождение последнего; завершение при выходе; запрет новых ключей после закрытия; отсутствие запуска на другой платформе; ошибка запуска и уведомления; восстановление helper; принудительное завершение зависшего helper; освобождение при исключении worker; отказ FFmpeg для потока и screen capture; отдельный флаг -d для захвата экрана.

Реальная проверка macOS: pmset -g assertions подтвердил появление PreventUserIdleSystemSleep для конкретного PID caffeinate и его исчезновение после последнего release. Сохранён отдельный stage7-power-proof.json с отфильтрованной строкой только созданного helper.

Отдельный интеграционный тест запускает собственный Python-процесс с caffeinate, принудительно завершает этот Python и проверяет исчезновение assertion. Постоянные параметры питания не менялись; Mac намеренно не усыплялся.

Сценарии паузы проверяют, что сеанс сохраняет ключ защиты до возобновления/остановки и не оставляет helper после завершения. Все прежние сценарии восстановления записи, deadline и восстановления расписания после пробуждения включены в общий прогон.

## Границы

Не проверялись физический сон Mac, закрытие крышки и реальные разрешения avfoundation. Удержание дисплея для screen capture проверено по сформированной команде; реальное системное assertion проверено для прямой записи. Защита не заменяет будильник для будущего расписания и не препятствует принудительному сну/разрядке/перезапуску системы. При паузе сеанс считается активным, поэтому защита сохраняется. Загрузки и отдельная операция восстановления старого файла при старте не получают новых ключей на этом этапе.

Ветка codex/stage-7-prevent-sleep. Исходная папка и установленное приложение не менялись; DMG, push и релиз не выполнялись.
